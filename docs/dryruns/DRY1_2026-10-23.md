## How it was kept safe

- **Scratch copy.** Every command ran in a detached scratch worktree off `origin/main` (2c13741d). Only this file was pushed.
- **A guard in every Python process.** A `sitecustomize.py` was loaded through `PYTHONPATH`. It refused, and logged, any non-read HTTP call to `*.googleapis.com` (the OAuth token call excepted), every call to `slack.com`, and any Groww URL containing "order". Reads went through.
- **A git wrapper first on `PATH`.** It refused `commit`, `push`, `pull`, `merge`, `rebase`, `reset` and the like.
- **No Slack token.** `FNO_SLACK_BOT_TOKEN` was unset for every run.
- **Result.** No command attempted a Drive write or a Slack post: the guard's log holds no Drive or Slack entry from my runs. The only refused git calls came from test suites that commit inside their own temporary repositories.
- **Local copies only.** Verified Drive downloads went only to the scratch worktree's `work/drive-cache/`. The DR1 records went to its own `receipts/records/`, never committed.
- **Lab previews.** The `lab preview` exception was approved, but its Slack post was refused by this session's tool permissions, so both previews were composed locally only.

## The real problems, with root causes

New ones first, then known ones confirmed. "Owner" is the piece's builder, for the orchestrator to route.

1. **The health check's desk row would mark every day late (f3). New.** The daily run starts the `decisions` step at `desk.timetable.decision_deadline` (15:12:00) by design. O8's `RunLogCheck` needs that step finished by the same deadline. It finishes about 1 second after, so the moment `Desk daily run` gets a `live_from`, every day reads "late". Strong evidence: the four run logs. Owner: O8 and E3.
2. **`global-cues verify` fails on all 1,981 FBIL rows (c4). New.** Whole-second `first_seen_at` against a microsecond `fetched_at`, with a strict compare (verify.py:63). The data is fine; the verifier is unusable for FBIL until fixed. Owner: A17.
3. **The lab's close source can write to Drive, including from `lab preview` (b4). New.** forecast_lab/wiring.py:98 (and price_ranges/wiring.py:90,114) builds `IndexFileCloses` on `build_index_close_files()`, which archives a missing NSE file to Drive. DR1 already moved to `stored_index_closes()`; the same split (a reader for previews and scoring, the writer only where archiving is meant) is needed here. No write happened in this run. Owner: FL1 and G13b.
4. **o9b-margins silently drops a main fix when merged (P-g1). New.** The branch carries its own copy of step 1b's `receipted_rows.py`. Taking its side removes main's two-line "series with nothing written yet reads empty" guard (story/o9-sync-file, judge 536) with no conflict marker on those lines. Merge o9b-cues first, then margins, then diff receipted_rows.py against main. `MOVED:` must read `data/vix data/global-cues data/margins`. Owner: O9b.
5. **After o9b-cues merges, cue tables in Drive are stale and nothing says so (P-g2). New.** Staleness is not a read failure, so `CueRows.problems` stays empty. `global-cues move` must run straight after the merge. A last-date check, Drive against the repository, before the repository copy is dropped would make it safe. Owner: O9b and A17.

Zero practice trades until about early December (reasoning only). Also open: 25% of legs "impossible". Owner: MS-SIM.
