# Review 126 — E4d shared displayed size (code)

**Scope:** `story/e4d-shared-size` at **e33ba70d**, request 205, E4d story, Response 195 addendum 1, `entry_check.py`, `entries.py` and `tests/desk/test_shared_size.py`. **Second reviewer:** ChatGPT, quality rule 9. **Verdict: PARTIAL — accept the safety mechanism; require transparent priority/opportunity reporting before treating results as strategy comparisons.** Evidence labels: strong evidence = inspected code or arithmetic; some evidence = reported judge tests; reasoning only = market interpretation. Judge 205's 6,578 tests and four plants are reported, not independently executed. Paper only.

## 1. First entry wins — PARTIAL (strong evidence for implementation; reasoning only for fairness)

The journal-backed sequential allocation correctly prevents an impossible same-book touch fill: 65 + 65 = **130**, so displayed size 100 or 129 cannot fund both, while 130 can. This is a defensible deterministic *paper execution policy*, not an unbiased allocation between strategies. `EntryDesk.enter` reads prior fills before checking the next entry, so an earlier strategy in Book 1's fixed order has priority even when its expected edge is weaker. A real trader might reduce sizes or choose a different order, but that would be a different, predeclared execution policy. **Do not reorder after observing outcomes.** Before scorecards compare strategies, report the fixed entry priority, `size_shared_in_book` refusals by strategy and their original opportunity counts. If a strategy systematically loses capacity, its realised book P&L must reflect that, while its hypothetical idea-quality score stays separate. No new allocation optimiser is justified.

## 2. Protective sell-back reservation — ACCEPT (strong evidence for code; reasoning only for economics)

`taken_units` adds held bought protection (opening buys less sold-back rows) to the **bid** requirement, in addition to actual sold fills. That is deliberately conservative: a held wing's hypothetical sell-back is not an executed sell order, so it can refuse an otherwise executable new short sale. But E4c promises the protection can be sold back at the entry snapshot; reserving that displayed bid capacity consistently across a book's entries is the safer model. Example: 65 held + 65 new short = 130 required; bid size 129 refuses. Disclose that this is a *conservative reservation*, not consumed exchange liquidity. It may depress fill rates, not necessarily expected return.

## 3. Exits, short buy-back and other books — ACCEPT with known limits (strong evidence for architecture)

**Same-snapshot exits:** the daily flow executes entries before exits, so exits do not release touch capacity before entry. Counting historical fills at the snapshot, including unwind rows, is conservative and consistent with that order; it can overstate consumed capacity when an earlier position is unwound, but cannot invent more available touch size. **Short-leg buy-back depth:** E4c already leaves it out; later exits can wait and are not guaranteed executable. Report pending exits. **Other books:** do not pool them: independent hypothetical accounts are evaluated separately, and pooling would arbitrarily favour the first book. These are known limits, not blockers for the existing paper policy.

## 4. E6 and scoreboard B missed opportunities — PARTIAL (strong evidence)

A refusal produces `not_opened`, no fill, no cash flow, no charges and no new-risk use. **E6/scoreboard B must count the refused entry as a missed execution opportunity of both the originating strategy and its book**, attributed specifically to `size_shared_in_book`; it is **not** a strategy's intentional skip or a losing filled trade. Preserve the D2 decision/opportunity in the denominator and report the attempted entry, reason and fill rate by strategy/book. E6's actual net P&L stays unchanged (zero for this unfilled attempt), and the owner's stop must use actual ledger risk, not hypothetical exposure. This is a reporting requirement for existing scorecards, not a new fill engine. A strategy-first allocation can otherwise make the later strategy look inactive rather than capacity-constrained.

## 5. Row order, other actions and duplicate contracts — PARTIAL (strong evidence for inspected code; reasoning only for remaining shapes)

`taken_units` matches **both snapshot ID and SHA**, excludes the current `trade_id` on a crash replay, counts every recorded row by side, and subtracts sold-back protective units from the held reservation. The inspected tests cover unwind, cross-book independence, and 129/130 boundaries. `EntryDesk.enter` returns a recorded terminal outcome before recalculating, so an ordinary rerun cannot emit a second refusal alert.

**Known limits:** (a) the code treats every non-`FILL_OPEN` action on an originally bought leg as a reduction of held protection. This is safe for the presently documented `FILL_UNWIND` and `FILL_CLOSE` actions but would need revisiting if a new action such as an adjustment is introduced; (b) the check does **not aggregate two legs of the same new entry sharing one contract/side**, because current STR1 structures have distinct contracts. Neither is a demonstrated normal-running bug. If either shape becomes supported, add a focused test before activation rather than speculative generic code.
